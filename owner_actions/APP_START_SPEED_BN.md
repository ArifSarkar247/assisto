# অ্যাপ খোলার গতি — আসল মাপা সংখ্যা (faststart, ১০ নভেম্বর)

> **এক কথায়:** আগে ইন্টারনেট থাকলে ২ GB ফোনে হোম খুলত **১.৯৮ সেকেন্ড**-এ (লক্ষ্যের একদম কিনারায়), কিন্তু **ইন্টারনেট না থাকলে হোমে ঢোকাই যেত না — লগইন পাতা আসত**, আর দুর্বল নেটে (নেট আছে কিন্তু সার্ভার সাড়া দেয় না) **৩০ সেকেন্ডেও কোনো পাতা আসেনি** (শুধু ঘুরন্ত চাকা)। My Circle চ্যাট তালিকা ইন্টারনেট থাকলেও **২.০ সেকেন্ড**, অফলাইনে খোলেই না। মূল কারণ একটাই: অ্যাপ খোলার সময় সার্ভারকে "আমি কে?" (/me) জিজ্ঞেস করে উত্তরের জন্য বসে থাকত। ঠিক করা হয়েছে (offline1st শাখার সাথে মিলে), পরের মাপ নিচে "পরে" কলামে।

**কোথায় মাপা:** GitHub-এর এমুলেটর — ২ GB RAM, ২ কোর, Android 13 (API 33), 720x1600, অ্যানিমেশন চালু। অ্যাপ PROFILE বিল্ড (রিলিজের মতো দ্রুত কোড), রানারের ভেতরের টেস্ট সার্ভার, আসল এনক্রিপ্টেড ২০০ মেসেজের চ্যাট। "অফলাইন" = বিমান মোড (নেট পুরো বন্ধ, প্রমাণ: ping unreachable)। "দুর্বল নেট" = নেট চালু কিন্তু সার্ভার জমে আছে (ক্যাপটিভ পোর্টাল / খারাপ 2G-র মতো)। প্রতিটা সংখ্যা ৩–৫ বারের মাঝামাঝি মান। রান: আগে ৪২৬৮০৩৪৫৫০৩, পরে — (চলছে)।
Firebase Test Lab-এর আসল সস্তা ফোন: **মাপা যায়নি** — GCP_TESTLAB_SA চাবি এখনো দেওয়া নেই (মালিকের কাজ)।

**My Circle কেন ২ সেকেন্ড:** তালিকা দেখানোর আগে সার্ভারে **পরপর ৩–৪টা প্রশ্ন** (সদস্য → চ্যাট → চাবি → তালিকা), প্রতিটার ১৫ সেকেন্ড সময়সীমা — দুর্বল নেটে ৪৫ সেকেন্ড পর্যন্ত চাকা, অফলাইনে "লোড হয়নি"। ঠিক করছে offline1st শাখা (ফোনে রাখা এনক্রিপ্টেড কপি থেকে সাথে সাথে, নেট পরে)।

## যা ঠিক করা হলো (শাখা agent/faststart)

1. **মাপার যন্ত্র:** প্রতিটা ধাপে সময়-চিহ্ন (শুধু CI-র মাপার বিল্ডে, আসল অ্যাপে শূন্য খরচ), নতুন CI কাজ `startspeed.yml` — নেট আছে / বিমান মোড / দুর্বল নেট, ঠান্ডা / গরম / উষ্ণ চালু, My Circle।
2. **প্রতিটা বিল্ডে CI পাহারা** (`android.yml` → start-time-guard): আসল রিলিজ APK, ২ GB এমুলেটর, বিমান মোডে — ঠান্ডা চালু ৫ বারের মাঝামাঝি < ২.৫ সেকেন্ড (২ সেকেন্ড লক্ষ্য + ২৫% এমুলেটর-ছাড়), গরম চালু < ১ সেকেন্ড; সীমা পেরোলে আরেকবার মেপে তারপর লাল। প্রথম মাপ: ঠান্ডা ১৪৮৮ ms ✅, গরম ১৯৫ ms ✅।
3. **ফোনের ডেটাবেস একসাথে পড়া** (৯টা পড়া পাশাপাশি, ফাইল একবারই খোলে)।
4. **অ্যাপ-খোলার বিজ্ঞাপন:** আগে বিজ্ঞাপন "আনো তারপর দেখাও" — হোম ব্যবহার শুরুর ৮–১৬ সেকেন্ড পরে হঠাৎ পর্দা ঢেকে যেত। এখন **শুধু আগে থেকে লোড থাকলে** দেখায়, না থাকলে এবার বাদ, পরের বারের জন্য চুপচাপ লোড। **অফলাইনে কখনো না**, প্রথমবার খোলায় কখনো না (আগেই ছিল), ঠান্ডা চালুতে স্পনসর কার্ড না, সার্ভারের উত্তর ১.৫ সেকেন্ডে না এলে বাদ।
5. **ছবি ফোনে রাখা:** হোমের Discover আর স্পনসর ছবি আগে প্রতি বার খুলতে নতুন করে নামত, অফলাইনে ফাঁকা বাক্স। এখন একবার নামলে ফোনে থাকে (সর্বোচ্চ ৩০০টা, পুরনোটা মুছে)।
6. **কম ডেটা মোড** (সেটিংস → "কম ডেটা মোড"): নতুন ছবি নামায় না (ফোনে থাকলে দেখায়), কলে কম ডেটা।
7. **APK আকার:** প্রতিটা বিল্ডে সবচেয়ে বড় অংশের তালিকা রানের সারাংশে, ১০০ MB ছাড়ালে লাল। ওয়েবসাইটের APK আগে থেকেই শুধু arm64 (একটা ABI), Play পায় AAB (প্রতি ফোনে নিজের অংশ)। R8 ছোট-করা চালু।

## সৎ সীমা / পরের ধাপ

- এমুলেটরের মাপ; সস্তা ARM ফোনে প্রসেস-চালুর ~৯৬০ ms অংশটা বেশি হতে পারে। Test Lab চাবি পেলে আসল ফোনে মাপা হবে।
- APK ৭৪ MB-এর বড় অংশ নেটিভ লাইব্রেরি (onnxruntime, ML Kit, WebRTC, media3) — ফিচার না কেটে ছোট করা যায় না; পরের ধাপ: ছবির AI মডেল প্রথম ব্যবহারে নামানো (Play Feature Delivery)।
- পাশে-ইনস্টল করা APK-তে Android-এর "বেসলাইন প্রোফাইল" নেই (Play-তে আছে) — পরের ধাপে বিবেচনা (নেটিভ পরিবর্তন লাগবে)।
- পুরনো বিল্ড থেকে আপডেটের পর **প্রথম** খোলায় একবার সর্বোচ্চ ৬ সেকেন্ড /me অপেক্ষা (তখনো ফোনে প্রোফাইল-কপি নেই); তারপর থেকে সবসময় ফোনের কপি দিয়ে সাথে সাথে।

## দুই-ফোন / নিজ-ফোন পরীক্ষা (মালিকের জন্য, ২ মিনিট)

1. অ্যাপ পুরো বন্ধ করুন (Recent থেকে সরান) → বিমান মোড চালু → অ্যাপ খুলুন: **হোম আসবে, লগইন পাতা নয়**, উপরে ছোট "অফলাইন" দাগ।
2. My Circle চাপুন: চ্যাট তালিকা ১ সেকেন্ডের মধ্যে, আগের মেসেজ পড়া যায়।
3. বিমান মোড বন্ধ → ২–৩ সেকেন্ডে সব তাজা হয়, অপেক্ষা-করা মেসেজ চলে যায় (অন্য ফোনে পৌঁছায়)।
4. সেটিংস → "কম ডেটা মোড" চালু → হোমে নতুন ছবি নামবে না, আগে দেখা ছবি থাকবে।
