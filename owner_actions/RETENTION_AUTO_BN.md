# রিটেনশন অটোমেশন (বড় সপ্তাহ H) — মালিকের নোট

**অবস্থা:** 🙈 লুকানো — সার্ভার-ফ্ল্যাগ `retention_auto` ডিফল্ট বন্ধ। Owner Admin → Features থেকে শুধু আপনার / টেস্টারের আইডিতে চালু করে পরীক্ষা করুন। ৯টি শর্ত পূর্ণ না হওয়া পর্যন্ত সবার জন্য চালু হবে না।

## এটা কী করে
বিজনেস প্ল্যানের দোকান-মালিক নিজের **পুরনো গ্রাহকদের** কাছে ছোট, ভদ্র, স্বয়ংক্রিয় মেসেজ চালু করতে পারেন — একবার সেট করলে নিজে থেকে চলে:

| অটোমেশন | কখন যায় | কারা পায় |
|---|---|---|
| ধন্যবাদ + মতামত চাওয়া | কেনার N দিন পর (ডিফল্ট ২) | যারা দোকানে কিনেছেন |
| অনেক দিন দেখা নেই | X দিন কোনো কেনা না হলে (ডিফল্ট ৪৫) | যারা আগে কিনেছেন (১ বছরের মধ্যে) |
| বাকির ভদ্র রিমাইন্ডার | বাকি থাকলে প্রতি N দিনে (ডিফল্ট ১৪, ন্যূনতম ৭) | খাতার গ্রাহক, ফোন নম্বরসহ |
| পণ্য আবার এসেছে | চাওয়া পণ্য স্টকে এলে, একবার | মালিক যাদের "কে কী চেয়েছেন"-এ লিখেছেন |
| জন্মদিনের শুভেচ্ছা | জন্মদিনে | গ্রাহক নিজে জন্মদিন জানালে মালিক যা লিখেছেন |

প্রতিটির জন্য: গ্রাহক-সংখ্যার প্রিভিউ, বাংলা+ইংরেজি মেসেজ (নাম/দোকান/পণ্য/দিন/বাকি নিজে বসে), চ্যানেল, পাঠানোর সময়, চালু/বন্ধ। ফলাফল: পাঠানো, পৌঁছেছে, উত্তর, বন্ধ করেছেন, মেসেজের পর কেনাকাটা ও বিক্রির টাকা (মেসেজের পর ৭ দিনের মধ্যে একই গ্রাহক কিনলে; শুধু সবশেষ মেসেজটি গোনা হয়), বাকির ক্ষেত্রে "রিমাইন্ডারের পর পরিশোধ", কেন কিছু যায়নি।

গ্রাহকের দিক: Assisto-তে "দোকানের মেসেজ" পাতা — প্রতিটি মেসেজে **উত্তর দিন** ও **বন্ধ করুন**।

## কড়া সীমা (সার্ভারে প্রয়োগ, অ্যাপ বদলালেও ভাঙে না)
- একজন গ্রাহককে **দিনে ১টি, সপ্তাহে ২টির বেশি নয়** — সব অটোমেশন মিলিয়ে। মালিক কমাতে পারেন, বাড়াতে পারেন না।
- এক দোকান থেকে **দিনে মোট সর্বোচ্চ ১০০টি** (Owner Admin → Pricing → `retention` ব্লকে বদলানো যায়, ১–১০০০ সীমায়)।
- **রাত ৯টা থেকে সকাল ৯টা কোনো মেসেজ নয়** (Asia/Dhaka)।
- **STOP সাথে সাথে:** অ্যাপে "বন্ধ করুন", WhatsApp/Messenger-এ "STOP"/"বন্ধ করুন"/"আর মেসেজ দিবেন না", SMS-এর লিংক — যেকোনো একটায় বন্ধ করলে সেই দোকানের **সব** অটোমেশন বন্ধ (AI এজেন্টের ফলো-আপও)। মালিকও "মেসেজের সীমা" থেকে কোনো নম্বর বন্ধ করতে পারেন।
- শুধু দোকানের নিজের গ্রাহক — বিক্রি, খাতা বা নিজে চাওয়া। **কোনো তালিকা আমদানির উপায় নেই**, অপরিচিত কাউকে নয়, কোনো কল নয়।
- প্রতি দোকানে সর্বোচ্চ ১০টি অটোমেশন; প্রতি রানে সর্বোচ্চ ৫০০০ গ্রাহক যাচাই।
- গ্রাহকের তথ্য শুধু সেই দোকানের; গোপনীয়তা নীতিতে "দোকানের স্বয়ংক্রিয় মেসেজ" অংশ যোগ হয়েছে।

## চ্যানেল ও খরচ
- **Assisto অ্যাপ (ডিফল্ট):** বিনামূল্যে (ক্রেডিট-সারি `retention_in_app` = ০, চাইলে Pricing-এ বাড়াতে পারেন)। গ্রাহকের ফোন নম্বরে Assisto অ্যাকাউন্ট থাকলেই যায়; না থাকলে ফলাফলে "গ্রাহক Assisto ব্যবহার করেন না" — মিথ্যা "পাঠানো" দেখায় না।
- **WhatsApp:** শুধু বিজনেস এজেন্টে যুক্ত অফিসিয়াল WhatsApp Cloud API নম্বর দিয়ে। গ্রাহকের শেষ মেসেজের ২৪ ঘণ্টার মধ্যে সাধারণ মেসেজ; তার পরে **শুধু Meta-অনুমোদিত টেমপ্লেট**। খরচ Meta-র প্রতি-মেসেজ দাম অনুযায়ী ক্রেডিট থেকে কাটে (Pricing → seller_agent → wa_cost_bdt, বিদ্যমান ব্যবস্থা); ক্রেডিট কম থাকলে আগেই আটকায়।
- **Messenger:** শুধু ২৪ ঘণ্টার মধ্যে (প্রচারের জন্য কোনো message tag ব্যবহার হয় না)।
- **SMS:** শুধু যুক্ত SMS গেটওয়ে দিয়ে; প্রতি SMS-অংশে "sms" ক্রেডিট (বাংলা ৭০ অক্ষরে ১ অংশ), শূন্য ক্রেডিটে যায় না, গেটওয়ে ব্যর্থ হলে ক্রেডিট ফেরত। প্রতিটি SMS-এ বন্ধ করার লিংক।

## Meta নিয়ম (WhatsApp টেমপ্লেট)
- ধন্যবাদ/ফিরে আসুন/স্টক/জন্মদিন = **Marketing** টেমপ্লেট। শুধু বাকির রিমাইন্ডার **Utility** হতে পারে — প্রচারের মেসেজ Utility টেমপ্লেটে দিলে সার্ভার ফিরিয়ে দেয়।
- টেমপ্লেটে "Stop promotions" বোতাম/উপায় থাকতে হবে, আর "Meta অনুমোদন দিয়েছে" টিক দিতে হবে — না হলে পাঠায় না।
- টেমপ্লেটের প্রথম ঘর `{{1}}`-এ গ্রাহকের নাম বসে।
- Marketing মেসেজের আগে গ্রাহকের WhatsApp-এ মেসেজ পাওয়ার সম্মতি থাকা Meta-র নিয়ম — দোকান নিজের গ্রাহক থেকেই নেবে।

## আপনার যা করতে হবে
1. ডিপ্লয়ের পর মাইগ্রেশন `0092_retention_auto` (ইন্টিগ্রেটর বুকিং-শাখার সাথে ক্রম ঠিক করবেন)।
2. ক্রন যোগ: `deploy/retention1/retention.cron` (প্রতি ১৫ মিনিটে `manage.py retention_run`)।
3. Owner Admin → Features → `retention_auto`: আপনার ও টেস্টারের আইডি allow-list-এ দিন।
4. (ঐচ্ছিক) SMS গেটওয়ে কী (Integrations → SMS), WhatsApp-এর জন্য Meta-তে অনুমোদিত টেমপ্লেট।
5. Play Data safety: নতুন কোনো অনুমতি নেই; "Messages" — দোকান থেকে আসা মেসেজ অ্যাপে দেখানো হয় (ব্যবসা-ব্যবহারকারীর তৈরি কনটেন্ট) — ঘোষণা হালনাগাদ বাকি।

## ১০ মিনিটের পরীক্ষা (দুই ফোন)
**ফোন A** = দোকান-মালিক (বিজনেস প্ল্যান), **ফোন B** = গ্রাহক (আলাদা Assisto অ্যাকাউন্ট)। দুজনের আইডি `retention_auto`-র allow-list-এ।
1. (A) বিজনেস → POS-এ B-র ফোন নম্বর দিয়ে গ্রাহক বানিয়ে একটা ছোট বিক্রি করুন।
2. (A) মেনু → ব্যবসা → **রিটেনশন অটোমেশন**। ৩ ধাপের গাইড দেখুন → "অটোমেশন তৈরি করুন"।
3. (A) "ধন্যবাদ + মতামত চাওয়া" → "কেনার কত দিন পর" = ১ → "কারা পাবেন"-এ সংখ্যা ১ ও "১ জন Assisto ব্যবহার করেন" দেখুন → মেসেজ দেখুন (শেষে "বন্ধ করুন" লাইন) → Assisto অ্যাপ → পাঠানোর সময় সকাল ৯টা → সেভ।
4. দ্রুত পরীক্ষার জন্য সার্ভারে: বিক্রির তারিখ ১ দিন পিছিয়ে দিন অথবা পরের দিন সকাল ৯টার পর অপেক্ষা করুন; তারপর `manage.py retention_run` (বা ক্রনের অপেক্ষা)।
5. (B) নোটিফিকেশন → "দোকানের মেসেজ" খুলে মেসেজ দেখুন → **উত্তর দিন** লিখুন "ভালো লেগেছে"।
6. (A) অটোমেশন কার্ড ট্যাপ → ফলাফল: পাঠানো ১, পৌঁছেছে ১, উত্তর ১।
7. (A) একই গ্রাহককে আরেকটা বিক্রি করুন → ফলাফলে "পরে কেনাকাটা ১" ও টাকা।
8. (B) **বন্ধ করুন** চাপুন → (A) "জন্মদিনের শুভেচ্ছা" বানিয়ে B-র জন্মদিন আজকের তারিখ দিন → রান করলেও B কিছু পায় না; ফলাফলে "বন্ধ করেছেন ১"।
9. রাত ৯টার পর `retention_run` চালান → কিছুই যায় না (চুপ থাকার সময়)।
10. (A) "মেসেজের সীমা" খুলে সপ্তাহের সীমা ২-এর বেশি করার চেষ্টা করুন — "+" বন্ধ থাকে।

## যা এখনো বাকি (সৎ তালিকা)
- আসল দুই ফোনে উপরের পরীক্ষা, ২ GB ফোনে গতি মাপা, রিয়ালিটি-অডিট ফ্লো।
- আসল WhatsApp টেমপ্লেট ও SMS গেটওয়ে দিয়ে লাইভ পাঠানো (কোডে টেস্ট-মোডে যাচাই হয়েছে)।
- CRM-এর লিড (B2B পাইপলাইন) এখনো অডিয়েন্সে নেই — শুধু দোকানের বিক্রি/খাতা/অনুরোধ।
- Play Data safety ঘোষণা হালনাগাদ।
