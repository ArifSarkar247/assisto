# কল স্কেলিং — কল-রিলে (TURN) সার্ভার কতটা নিতে পারে, কখন বাড়াবেন

*(t9-turnscale, ২২ অক্টোবর ২০২৬। সহজ ভাষায়, মালিকের জন্য।)*

## ১. TURN কী, কেন দরকার

দুই ফোনের ভয়েস/ভিডিও কল সাধারণত সরাসরি (P2P) চলে — তাতে আমাদের কোনো খরচ নেই।
কিছু মোবাইল নেটওয়ার্কে সরাসরি পথ পাওয়া যায় না; তখন কলটি আমাদের **রিলে সার্ভার
(TURN, turn.lifeassisto.com)** দিয়ে যায়। রিলে হওয়া কলেই সার্ভারের CPU, নেটওয়ার্ক আর
AWS-এর ডেটা খরচ লাগে।

গুরুত্বপূর্ণ: **প্রতিটি কল শুরুর সময়** (সরাসরি হলেও) দুই ফোন রিলে সার্ভারে একটি করে
"জায়গা" (allocation) বুক করে রাখে — আজকের সেটিংয়ে প্রতি ফোনে ২টি (UDP + TCP), অর্থাৎ
**প্রতি কলে ৪টি**। TLS (5349) যোগ হলে প্রতি কলে ৬টি।

## ২. এই সার্ভার এখন কতটা নিতে পারে (মাপা + হিসাব)

সার্ভার: AWS t3.large (২ vCPU, 7.8 GB RAM)। নেটওয়ার্কের স্থায়ী সীমা ≈ 512 Mbit/s
(অল্প সময়ের জন্য 5 Gbit/s পর্যন্ত)। CPU "burstable": স্থায়ীভাবে প্রতি vCPU-এর ৩০%,
বেশি চালালে জমানো ক্রেডিট খরচ হয় (unlimited মোডে বাড়তি বিল)।

**মাপা (২২ অক্টোবর, ছোট টেস্ট, ২ মিনিটের কম):** একই সার্ভার থেকে `turnutils_uclient`
দিয়ে নকল কল চালানো হয়েছে (দুই দিকেই রিলে হওয়া কল)। কোনো প্যাকেট হারায়নি।

| নকল কল | coturn CPU (এক vCPU-এর) | প্রতি কলে |
|---|---|---|
| ১০টি ভয়েস-ধরন কল | গড় ২.৪%, সর্বোচ্চ ৫% | — |
| ১৮টি ভয়েস-ধরন কল | স্থির অবস্থায় ৫–৭% | ≈ ০.৩৩% |
| ১৮টি ভিডিও-ধরন কল (0.8 Mbit/s প্রতি দিকে) | স্থির অবস্থায় ৮–১০% | ≈ ০.৫৫% |

(সীমাবদ্ধতা: টেস্টের ট্রাফিক সার্ভারের ভেতরেই ঘুরেছে, তাই এটি CPU মাপে — AWS নেটওয়ার্কের
সীমা মাপেনি; নেটওয়ার্কের সংখ্যা AWS-এর প্রকাশিত মান থেকে হিসাব করা।)

**হিসাব থেকে ধারণক্ষমতা** (coturn-কে এক vCPU-এর ৩০% আর 250 Mbit/s দিলে, বাকিটা অ্যাপের
API-র জন্য):

| | স্থায়ীভাবে একসাথে | কেন |
|---|---|---|
| রিলে হওয়া **ভয়েস** কল | ≈ **৯০টি** | CPU (০.৩৩% × ৯০ ≈ ৩০%) — নেটওয়ার্ক তখনো মাত্র ≈ ৯ Mbit/s |
| রিলে হওয়া **ভিডিও** কল | ≈ **৪৫টি** | CPU (প্রতি কলে ≈ ০.৬৫%); নেটওয়ার্কে ≈ ১১৯টি পর্যন্ত (প্রতি কলে ≈ 2.1 Mbit/s) |
| মোট কল (সরাসরি + রিলে) | ≈ ৪০০+ | সাধারণত ১০–২৫% কলেই রিলে লাগে |

### ⚠️ আজকের সেটিংয়ে আসল সীমা আরও কম: ≈ ৩১টি কল

coturn প্রতিটি allocation-এর জন্য `max-bps` (2 Mbit/s) আগেই "রিজার্ভ" করে রাখে, আর মোট
`bps-capacity` (250 Mbit/s) শেষ হলে নতুন কল ফিরিয়ে দেয় ("486 Allocation Bandwidth Quota
Reached")। 250 ÷ 2 = **১২৫টি allocation** = প্রতি কলে ৪টি ধরে **≈ ৩১টি কল একসাথে** (সরাসরি কলও
গোনা হয়)। তাই নিচের সেটিং বদল প্রস্তাব করা হয়েছে (ডেভেলপার/ইন্টিগ্রেটর করবেন):

| সেটিং | এখন | প্রস্তাব | কেন |
|---|---|---|---|
| `total-quota` | 600 | **1200** | ২০০টি একসাথে কল × ৬ allocation; allocation খুব সস্তা (একটি পোর্ট) |
| `bps-capacity` | 31250000 | **0 (বন্ধ)** | রিজার্ভেশনের কৃত্রিম ১২৫-সীমা সরে যায়; ব্যান্ডউইথ পাহারা দেবে আমাদের ৭০% সতর্কতা |
| `max-bps` | 250000 | **250000 (একই)** | প্রতি কল-পথে 2 Mbit/s — মোবাইলে ৭২০p ভিডিওর জন্য যথেষ্ট; একটি খারাপ ক্লায়েন্ট পুরো সার্ভার খেতে পারবে না |
| `user-quota` | 40 | **40 (একই)** | একজন ব্যবহারকারী একসাথে কয়েকটি কল/রিডায়াল করতে পারেন |

বদলের পরে: ভয়েস ≈ ৯০, ভিডিও ≈ ৪৫ রিলে কল একসাথে (স্থায়ী); অল্প সময়ের ভিড়ে CPU ক্রেডিট
দিয়ে এর ২–৩ গুণ।

## ৩. খরচ — প্রতি রিলে মিনিট

AWS শুধু সার্ভার থেকে **বাইরে যাওয়া** ডেটার বিল করে (ভেতরে আসা ফ্রি):
মুম্বাই (ap-south-1) **USD 0.1093 প্রতি GB** (প্রথম 10 TB/মাস; মাসের প্রথম 100 GB ফ্রি —
হিসাবে বাদ দেওয়া হয়নি, তাই আসল খরচ একটু কম)। দাম বদলালে সার্ভারের
`TURN_EGRESS_USD_PER_GB` বদলান।

| | প্রতি মিনিট ডেটা | প্রতি মিনিট খরচ (≈ ৳১২০/USD) |
|---|---|---|
| রিলে ভয়েস কল (আনুমানিক) | ≈ 0.78 MB | ≈ **৳০.০১** |
| রিলে ভিডিও কল (আনুমানিক) | ≈ 15.8 MB | ≈ **৳০.১৯** |

Owner Admin → **লাভ-ক্ষতি** ও **কল রিলে (TURN)** পাতায় আসল সংখ্যা দেখা যায়। যথেষ্ট রিলে কলের
বাইট মাপা হলে (কমপক্ষে ৩টি কল) "মাপা" দেখাবে, তার আগে "আনুমানিক" লেবেল থাকবে।

## ৪. দ্বিতীয় TURN সার্ভার যোগ করা (অ্যাপ আপডেট লাগে না)

১. নতুন ছোট সার্ভার চালু করুন (Ubuntu), তাতে coturn বসান — এই সার্ভারের মতো একই
   `turnserver.conf` (realm, denied-peer-ip লাইন, external-ip নতুন সার্ভারের IP)।
   সিক্রেট: একই `static-auth-secret` রাখুন, অথবা নতুন সিক্রেট দিন এবং API সার্ভারের env-এ
   `TURN2_SECRET=...` হিসেবে রাখুন (গিটে কখনো নয়)।
২. AWS Security Group: UDP/TCP 3478, TCP 5349, UDP 49152–65535 খুলুন।
৩. DNS: `turn2.lifeassisto.com` → নতুন সার্ভারের Elastic IP। TLS সার্টিফিকেট (Let's Encrypt)
   ওই নামে নিন।
৪. বাইরে থেকে পরীক্ষা: GitHub-এর TURN probe workflow চালান (UDP, TCP, TLS তিনটিই OK হতে হবে)।
৫. Owner Admin → **কল রিলে (TURN)** → সার্ভার তালিকায় লিখুন:
   ```
   turn.lifeassisto.com
   turn2.lifeassisto.com|w=2|secret_env=TURN2_SECRET
   ```
   (`w=2` = নতুন সার্ভারে দ্বিগুণ কল পাঠাবে; একই সিক্রেট হলে `secret_env` অংশ লাগবে না।)
   Save চাপুন।
৬. পরের কল থেকেই ফোনগুলো দুই সার্ভারই পাবে। এক মিনিট পর "শেষ STUN পরীক্ষা"-য় দুটিই
   "সাড়া দিচ্ছে" দেখাবে। কোনো সার্ভার পরপর ২ বার সাড়া না দিলে সেটি আপনাআপনি তালিকা থেকে
   বাদ যায়, ফিরে এলে আবার যুক্ত হয়।

মনে রাখবেন: তালিকা চালু করলে ফোন TLS (5349) পথও পায় — কঠোর নেটওয়ার্কে কল আরও সফল হয়,
কিন্তু প্রতি কলে allocation ৪ থেকে ৬ হয়। তাই আগে ২ নম্বর অংশের সেটিং বদল করে নিন।

## ৫. কখন TURN-কে আলাদা ছোট সার্ভারে সরাবেন — নির্দিষ্ট সংকেত

নিচের যেকোনো **একটি** সত্যি হলে আলাদা TURN সার্ভার নিন (ধাপ ৪-এর মতো, তারপর তালিকা থেকে
এই সার্ভার সরিয়ে দিন বা কম ওজন দিন):

* একসাথে রিলে কল **≥ ৬০টি** (ভিডিও কলকে ২টি ধরে) টানা ১৫ মিনিট, সপ্তাহে ৩ দিন বা বেশি।
  (Owner Admin-এ "রিলে অ্যালোকেশন" ≈ ২৪০+ এর আশেপাশে।)
* TURN CPU **এক vCPU-এর ২৫%-এর বেশি** টানা ১৫ মিনিট, অথবা **CPU steal ≥ ১০%**, অথবা AWS
  CloudWatch-এ CPUCreditBalance ২০%-এর নিচে — সপ্তাহে ২ দিন।
* রিলে ব্যান্ডউইথ **≥ 175 Mbit/s (বাজেটের ৭০%)** টানা ১০ মিনিট।
* অ্যাপের API ধীর হচ্ছে আর একই সময়ে রিলে ব্যস্ত।

প্রস্তাবিত সার্ভার: **t4g.small** (২ vCPU, 2 GB, 5 Gbit/s পর্যন্ত) — আনুমানিক
**USD ১২–১৭/মাস** (সার্ভার + পাবলিক IP USD ৩.৬ + ডিস্ক)। খুব বেশি ভিডিও হলে
**c7gn.medium** (নেটওয়ার্ক-শক্তিশালী) — আনুমানিক **USD ৫০/মাস**। (আনুমানিক; কেনার আগে
AWS Pricing Calculator-এ মুম্বাই অঞ্চলের দাম দেখে নিন।) ডেটার খরচ (প্রতি GB) সার্ভার বদলালেও
একই থাকে।

## ৬. ম্যানেজড TURN ওভারফ্লো (Cloudflare) — ডিফল্ট বন্ধ

আমাদের সার্ভার ভরে গেলে বা বন্ধ থাকলে বাড়তি কল Cloudflare-এর TURN দিয়ে চালানো যায়।
এর আলাদা প্রতি-GB খরচ আছে, তাই ডিফল্ট **বন্ধ**।

চালু করতে:
১. dash.cloudflare.com → Calls → TURN → TURN key বানান।
২. Owner Admin → **ইন্টিগ্রেশন ও কি** → "Managed TURN overflow (Cloudflare Calls)":
   Turn Token ID, API Token দিন; mode = `overflow` (শুধু ভরে গেলে) বা `always`;
   threshold_pct = `70`; enabled = `on` → **Save** → **Test**।
৩. Test সফল হলেই চালু হয়। key কখনো অ্যাপে যায় না — সার্ভার প্রতি কলের জন্য স্বল্পমেয়াদি
   পাসওয়ার্ড বানিয়ে দেয়।
৪. বন্ধ করতে: enabled = `off` → Save।

সততা: এই অংশটি Cloudflare-এর আসল সার্ভারের সাথে এখনো পরীক্ষা করা হয়নি (শুধু নকল
উত্তর দিয়ে টেস্ট)। প্রথমবার চালু করে Test চাপলেই আসল যাচাই হবে।

## ৭. সতর্কতাগুলোর মানে (পুশ/ইমেইল + অ্যাপের অ্যালার্ট)

প্রতি মিনিটে সার্ভার মাপ নেয়; সীমায় পৌঁছানোর **আগেই** জানায়, একই সতর্কতা ৬০ মিনিটে একবারের
বেশি নয়, ঠিক হয়ে গেলে "back to normal" বার্তা।

| সতর্কতা | মানে | কী করবেন |
|---|---|---|
| TURN allocations …% | allocation সীমার ৭০% ভরা | শীঘ্রই নতুন কল ফিরে যেতে পারে — ২ নম্বর অংশের সেটিং বদল / দ্বিতীয় সার্ভার |
| TURN bandwidth …% | রিলে ব্যান্ডউইথ বাজেটের ৭০% | ভিডিও কল বেশি — দ্বিতীয় সার্ভার বা ওভারফ্লো চালু |
| 486 quota reached | গত ৫ মিনিটে সার্ভার কল ফিরিয়ে দিয়েছে | জরুরি: সেটিং বাড়ান বা ওভারফ্লো চালু করুন |
| turnserver CPU …% | রিলের CPU বেশি | আলাদা TURN সার্ভারের সময় হয়েছে (৫ নম্বর অংশ) |
| CPU steal …% | AWS-এর CPU ক্রেডিট শেষ/ভিড় | একই — আলাদা সার্ভার বা বড় সার্ভার |
| server not answering STUN | কোনো TURN সার্ভার সাড়া দিচ্ছে না | সার্ভার/coturn চালু আছে কি দেখুন; তালিকা থেকে সেটি আপনাআপনি বাদ গেছে |

সব সীমা Owner Admin → **কল রিলে (TURN)** → "সতর্কতার সীমা"-তে বদলানো যায়।
