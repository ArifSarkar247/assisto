# ফাঁকের তালিকা — ভয়েস ও ভিডিও কলের মান (শাখা calls-quality · ১৮ Nov)

দুই এমুলেটরে দুটি আলাদা Assisto অ্যাপ একে অপরকে কল করে (calls2emu)। এবার নতুন পরীক্ষা: TURN সার্ভার দিয়ে কল, ৩G-এর মতো খারাপ নেট, Wi-Fi থেকে মোবাইল ডাটায় যাওয়া, PiP (ছোট ভাসমান ভিডিও), স্পিকার/ইয়ারপিস। প্রতিটি সংখ্যা ফোনের নিজের মাপা (WebRTC stats), টেস্টের অনুমান নয়।

## যা মাপা হলো (calls2emu, দুই এমুলেটর)
- **TURN relay (১৮q_relay):** দুই দিকেই শুধু relay; ১.২ সেকেন্ডে দুদিকে প্রথম ছবি; ভিডিও + অডিও দুদিকে (রান 44272508208)।
- **৩G-এর মতো নেট (১৮q_lossy):** ~৩৫০ ms RTT, ~৩% loss। অডিও চলেছে (সবচেয়ে বড় ফাঁক ~১.৫ সে)। ভিডিও ছোট হয়ে চলেছে, libwebrtc-র নিজের মাপে freeze ~০.৮ সে। ৪০০ kbit-এ নামালে দুই ফোনই ছবি ছোট করেছে, বন্ধ করেনি।
- **নেট বদল (১৮q_netswitch):** Wi-Fi বন্ধ → মোবাইল ডাটা → Wi-Fi চালু; A কলকারী এবং A গ্রহণকারী দুইভাবেই।
- **PiP (১৮q_pip):** PiP-এ দুদিকে ভিডিও (সবচেয়ে বড় ফাঁক <০.৮ সে), অ্যাপে ফিরলে ২.৫ সেকেন্ডে পুরো পর্দা।
- **অডিও রুট (১৮q_audio):** পর্দা = Android-এর আসল রুট; বারবার বদলের পরেও দুদিকে অডিও চলে।

**সৎ সীমা:** দুটি এমুলেটরই একটি CI কম্পিউটারে চলে (সফটওয়্যার VP8, ১–৮ fps)। "মোবাইল ডাটা" আসলে এমুলেটরের নকল রেডিও। এমুলেটরে ইয়ারপিস নেই, তাই আসল ইয়ারপিস ↔ স্পিকার বদল প্রমাণ হয় unit test-এ ও দুই-ফোনের পরীক্ষায়। ৭২০p পর্যন্ত ওঠা প্রমাণ হয় unit test-এ, কারণ এমুলেটরের uplink ~৩০০ kbps।

## দুই-ফোনে মালিকের ছোট পরীক্ষা (১০ মিনিট)
১. ফোন ক থেকে ফোন খ-তে ভিডিও কল করুন → ক-তে Wi-Fi বন্ধ করুন। ৫ সেকেন্ডের মধ্যে কল ফিরে আসবে, কাটবে না। Wi-Fi আবার চালু করুন, তখনও কল চলবে।
২. কলের মধ্যে হোম চাপুন → ছোট ভাসমান ভিডিও দেখাবে → সেটায় চাপুন → পুরো কল ফিরবে।
৩. ভয়েস কলে "স্পিকার" চাপুন → আওয়াজ লাউডস্পিকারে। আবার চাপুন → কানের স্পিকারে।
৪. লিফট বা বেসমেন্টের মতো দুর্বল নেটে ভিডিও কল করুন → ছবি ছোট/ধীর হবে, বন্ধ হবে না, পর্দায় "সংযোগ দুর্বল" দেখাবে।
