# E2E প্রমাণ — ৮টি মূল কাজ, এমুলেটর ও আসল ফোনে (e2eproof)

**নিয়ম (WORLD CLASS):** কাজ শেষ বলার আগে প্রমাণ লাগবে, মানে প্রধান কাজগুলোর স্ক্রিপ্ট-চালিত E2E পরীক্ষা, এমুলেটরে ও Firebase Test Lab-এ।
**বোর্ডের নিয়ম:** `QUALITY_BOARD_BN.md`-এর স্কোর (১) "আসল ফোনে শেষ পর্যন্ত কাজ করে" **৫-এর উপরে উঠবে শুধু তখনই**, যখন ওই সারির পাশে এই workflow-এর একটি **সবুজ রানের লিংক** থাকবে। এমুলেটর সবুজ হলে সর্বোচ্চ ৭। আসল ফোনে (Test Lab) সবুজ হলে ৮ পর্যন্ত। ৯–১০ পেতে মালিকের দুই-ফোন পরীক্ষাও লাগবে। লিংক না থাকলে স্কোর ৫-এর বেশি হবে না।

## কীভাবে চলে, কিসে টাকা লাগে না

- **এমুলেটর (`.github/workflows/e2e.yml` → job `emulator`):** প্রতি রাত ০৩:০০-এ (বাংলাদেশ সময়) চলে, আর GitHub-এর Actions পাতা থেকে "Run workflow" চাপলেও চলে। রানারের ভেতরেই একটা ফেলে-দেওয়া সার্ভার চালু হয়। লাইভ সার্ভার বা লাইভ ডেটাবেস কখনো ছোঁয়া হয় না।
- **নকল (শুধু CI-তে), `backend/ci_e2e`:** AI উত্তর, ছবির উত্তর, SMS কোড (`135790`), Google Places (Chandra), push আর নকল ঘড়ি। এগুলো শুধু নেটওয়ার্কের দরজায় বসানো, ভেতরের সার্ভার-কোড আসল। নকল উত্তরের শেষে "(CI)" লেখা থাকে, তাই স্ক্রিনশটকে কেউ আসল AI-উত্তর ভাববে না। Gemini/Claude-এর আসল key লাগে না, টাকাও খরচ হয় না।
- **আসল ফোন (job `testlab`):** একই ৮টি ফ্লো Test Lab-এর ৩টি আসল ফোনে চলে, বাংলাদেশে চালু ব্র্যান্ড আগে বাছা হয় (Samsung/Xiaomi/OPPO/realme, ক্যাটালগে যা আছে)। শুধু ফ্রি Spark কোটা ব্যবহার হয় (দিনে ৫টি আসল-ফোন টেস্ট; এখানে ৩টি)। রাতে চলে, বা "Run workflow"-এ `testlab` টিক দিলে চলে।

## মালিকের কাজ (একবারই)

এখন **GCP_TESTLAB_SA** secret নেই। তাই আসল-ফোন অংশ "NOT RUN — secret missing" লিখে থামে, ভুল সবুজ দেখায় না। চালু করতে:
1. `owner_actions/TESTLAB_SETUP.md`-এর ধাপ ১ (দুটি API চালু), ৩ (service account + JSON key) ও ৪ (GitHub → Settings → Secrets → Actions → **New repository secret**, নাম `GCP_TESTLAB_SA`, মান = পুরো JSON) করুন।
2. Firebase প্ল্যান **Spark (ফ্রি)**-ই রাখুন। Blaze-এ যাবেন না, বিলিং কার্ড লাগবে না।
কোনো টাকা খরচ হবে না।

## ফল কীভাবে পড়বেন

1. GitHub → Actions → **E2E proof** → শেষ রান খুলুন। সবুজ টিক মানে ৮টি ফ্লোই পাস করেছে (Care Call মার্জ না হওয়া পর্যন্ত সেটা skip হিসেবে গোনা হয়)।
2. রান পাতার Summary-তে টেবিল থাকে: ফ্লো, বোর্ড-সারি, পাস/ফেল, সময়, কোন ধাপে ভেঙেছে।
3. Artifacts → **e2e-proof-emulator** (আর **e2e-proof-testlab**) ডাউনলোড করুন। ভেতরে আছে:
   - `e2e_proof.json`: প্রতিটি ধাপের নাম, শুরুর সময় (`at_ms`), কতক্ষণ লেগেছে (`ms`), স্ক্রিনশটের নাম, ভুল।
   - `shots/`: প্রতিটি ধাপের ছবি।
   - `outbox.jsonl`: সার্ভার কী "পাঠিয়েছে" (SMS, push, AI)।
4. বোর্ডে স্কোর বাড়ালে ওই সারিতে রানের লিংক (`run_url`) লিখে দিন।

## দুই-ফোনে নিজে পরীক্ষা (৫ মিনিট)

দুটি ফোনে Assisto খুলুন (A ও B, একে অপরের My Circle-এ)।
1. A: চ্যাটে "বাংলাদেশের রাজধানী কোথায়?" লিখুন। বাংলায় উত্তর আসবে।
2. A→B: একটি ছবি "একবার দেখা" চালু করে পাঠান। B একবার খুলতে পারবে, দ্বিতীয়বার পারবে না।
3. A: নিরাপদ যাত্রায় "Chandra" লিখে খুঁজে B-কে watcher করে যাত্রা শুরু করুন। B লাইভ দেখবে।
4. A: SOS চেপে ধরুন। B-র ফোনে সাথে সাথে বাজবে।
5. A: "৩ মিনিট পরে ওষুধ খাওয়ার কথা মনে করিয়ে দাও" লিখে হ্যাঁ চাপুন। ৩ মিনিট পর নোটিফিকেশন আসবে।
